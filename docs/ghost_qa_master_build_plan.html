What Ghost QA is — 5 layers
Layer 1 — Trigger
GitHub webhook
GitHub Webhooks UiPath API Workflows Python Flask / FastAPI
Every time a PR is opened or a commit pushed, GitHub sends a signal. This layer catches it and starts the agent. This is your entry point into the whole system.
Layer 2 — Brain
LLM agent reads intent
Claude API / OpenAI UiPath Agent Builder Claude Code (bonus pts)
The agent reads the PR diff and any linked ticket. It understands WHAT changed and WHY, then generates test cases targeting what could break. This is the core of Ghost QA's intelligence.
Layer 3 — Execution
UiPath Test Cloud runs tests
UiPath Test Cloud UiPath Studio (test cases) Target SaaS app
The generated test cases are executed against your target app inside UiPath Test Cloud. Results come back as pass/fail with details. This is the platform usage judges will scrutinise most.
Layer 4 — Human gate
Action Center approval
UiPath Action Center UiPath Orchestrator
Before the test suite runs in full, a human (the dev or QA lead) reviews and approves it via Action Center. This is mandatory for the hackathon — it satisfies the human-in-the-loop requirement judges check for.
Layer 5 — Output
Risk report + PR comment
GitHub API Slack webhook (optional) HTML Risk Report
Results are posted back to the GitHub PR as a comment: which tests passed, which failed, what risk was detected. This closes the loop and makes the demo visual and concrete.
